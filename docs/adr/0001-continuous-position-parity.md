# 加密自动驾驶采用连续仓位模型，对齐回测

自动驾驶（第四步）在加密永续合约上采用连续目标仓位 `tanh(factor)`，每 bar 收盘把实际仓位向目标对齐，**不设单笔止盈/止损/保护单**。

## 为什么

用户明确要求“下单平仓逻辑完全与回测一致，即连续仓位”。这也是对仓库中**已损坏的奇偶性**的真正修复：旧 MT5 路径用 `target_to_direction()` 把 `tanh` 塌缩成离散 {-1, 0, +1}（`strategy_manager/signal.py:59-66`），与回测的连续打分（`model_core/backtest.py:426-429`）不一致；且 `execution.trader` 已被移除为 stub，当前没有任何实盘下单路径。

## 代价 / 后果

- 放弃参考文档《自动量化交易程序提示词文档》中的离散体系（保护单、止盈止损、reduceOnly、同币种去重、最大持仓数）——这些在连续回测里不存在，进入自动驾驶就会破坏奇偶性。
- 信号错误时只能靠 `tanh` 翻转来减仓，**没有单笔兜底**。账户级安全交给独立的运营熔断（见后续 ADR），它在策略逻辑层之外，不破坏奇偶性。
- 连续调仓在加密 perp 上意味着高频再平衡（如 H1 → 每标的 24 笔/天），对真实手续费/滑点/资金费极敏感——这些差异在 ADR-0002 起单独处理。
