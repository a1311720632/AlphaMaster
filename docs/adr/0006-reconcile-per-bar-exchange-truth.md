# 对账：每 bar 以交易所为准，靠下根 bar 的 delta 自愈

每个 bar 收盘下单前先 `fetch_positions` 与本地对账；不一致只告警，以**交易所实际持仓**为基准计算本期 `delta = target − actual_exchange`。孤儿单（交易所有仓、本地无策略）→ 告警 + 可选全平。

## 为什么

连续调仓模型在这里比离散模型有结构性的鲁棒性优势：每根 bar 都重新算 delta，所以任何漂移——部分成交、手动干预、订单被拒、资金费引起的保证金变动——都会被**下一根 bar 的 delta 自动修正**，不需要离散票据模型那套对账状态机。以交易所为准（而非本地账本）正是为了让这个自愈成立；若以本地为准，delta 基于过时的 actual，漂移会累积。

## 代价 / 后果

- 每 bar 一次 `fetch_positions` 是额外 API 调用；OKX 有频率限制，需在执行后端做节流与重试。
- “自愈”不是瞬时：本期未成交的漂移要到下根 bar 才修正，期间实际仓位短暂偏离目标——落入告警监控披露，不触发熔断。
- 孤儿单是真正的异常（策略不该有却有仓），不能靠 delta 自愈（因为本地无目标），单独走“告警 + 可选全平”。
- paper 模式无交易所，对账不适用；testnet/live 才走本 ADR。

## 放弃的方案

- 仅启动 + 定期对账：更省 API，但 bar 间漂移在检查间隔内累积，调仓基于过时的 actual。
- 本地账本优先：抵消连续模型的自愈优势，漂移不修正，连续模型下不推荐。
