# 安全覆写：运营熔断破坏奇偶性，告警监控不破坏

没有单笔止盈止损（ADR-0001）的前提下，账户级安全分两类：

- **运营熔断**（破坏奇偶性，但有意为之）：从启动权益起算回撤超阈（默认 −10%，对齐 FTMO 最大亏损）→ 全平 + 停止 + 告警；连续 N bar 连不上交易所或数据脏 → 停止下单。
- **告警监控**（不动仓位，不破坏奇偶性）：本地↔交易所持仓不一致、资金费异常、未成交漂移、孤儿单——只记录和通知，不改仓位。

## 为什么

连续调仓模型下没有“单笔”可保护；账户级最大回撤是唯一兜底。断网/数据脏时若继续调仓，等于在错误信号上交易，必须停。把“改仓位”与“不改仓位”严格分开，让奇偶性的破坏被限制在运营熔断这一小片可解释区域，其余风险只进告警、不悄悄扭曲仓位。

## 代价 / 后果

- 运营熔断一旦触发会**偏离策略目标仓位**（全平或停止调仓），这是用奇偶性换安全，可解释、可回滚（重置熔断需人工）。
- 默认回撤阈值 −10% 是 FTMO 对齐值；实盘应根据账户大小和风险偏好调整，作为配置项。
- 告警监控里的“账实不一致”本身不触发平仓——连续模型靠下根 bar 的 delta 自愈（见 ADR-0006 对账策略）。

## 放弃的方案

- 仅最大回撤熔断：最简，但断网/数据脏时仍会基于错误信号调仓。
- 完整 FTMO 风控套件（每日回撤 + 单方向暴露上限 + 滑点拒绝 + 资金费过滤）：最安全，但滑点拒绝/暴露上限会让实际仓位 ≠ 目标，持续破坏奇偶性，且 v1 单标的下每日回撤/暴露上限意义有限。
